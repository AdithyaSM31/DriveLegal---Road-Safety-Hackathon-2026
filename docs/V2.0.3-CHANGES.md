# Android 2.0.3

- Speed display stays at 0 while acquiring GPS, with the acquisition/unavailable state visible; a measured stationary speed is also 0. Stationary GPS updates are no longer suppressed by a minimum travel distance.
- Foreground location starts after sign-in/guest permission approval. No background location service.
- Weather loads automatically and refreshes every 10 minutes. OpenStreetMap maxspeed tags are checked every minute, or after 100 m with a 20-second minimum interval. These are nearby map estimates, not map matching; conflicting or missing tags show an unknown limit. Posted signs take precedence; manual override remains available.
- State jurisdiction follows Android reverse geocoding, checked at most every two minutes. Selecting a jurisdiction manually disables automatic selection; Choose jurisdiction → Use GPS state automatically restores it. Unsupported states show a national baseline and a coverage notice.
- Android accepts both the current Render chat format and the newer response mode/citations format. The selected/detected state is included in the request so the legacy server receives jurisdiction context. Network failure uses an explicitly labelled offline fallback. The Groq key stays in Render environment variables and is never included in the APK.
- Firebase photoURL appears in the Home header, with initials if no photo can load.

The deployed Render chat endpoint returned an online response during this update. No backend deployment or environment changes were made. Real-device GPS, road coverage, reverse geocoding and Google-account photo require field validation.

- The activity requests the highest advertised refresh rate at the current display resolution using preferredRefreshRate, and updates the preference after display changes. Android retains control over battery/thermal/user display constraints. No continuous rendering loop is introduced.
